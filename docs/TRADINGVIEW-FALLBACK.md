# TradingView احتياطيًا لبيانات MT5 — الترقية024

الخادم يقبل بيانات `OANDA:XAUUSD` على M1 عبر `/api/tradingview/ingest` بمفتاح خاص بإدخال الأسعار فقط. رمز `BYBIT:XAUUSDT.P` أو أي رمز آخر مرفوض. السكريبت الشخصي يولد JSON من الشموع القياسية المكتملة، ولا يرسل حسابًا أو أوامر تداول أو مفتاح وسيط. `key` مفتاح سعر محدود مستقل، يُزال قبل الحفظ، ويحتفظ الخادم ببصمته فقط. يجب عدم نشر الملف الشخصي أو المفتاح. القالب العام `tradingview/xtele-feed.pine` بلا مفتاح.

## التفعيل في TradingView

1. افتح شارت **OANDA:XAUUSD** القياسي، فريم **1m**. لا تستخدم Heikin Ashi أو Renko أو رمز Bybit.
2. في Pine Editor، الصق محتوى الملف الشخصي `xtele-feed-private.pine`، واحفظه في حسابك الخاص ثم Add to chart. قد تحتاج عرض سطح المكتب أو كمبيوتر لإظهار المحرر. لا تنشر السكريبت علنًا.
3. Create alert، ومن Condition اختر **xtele OANDA M1 fallback feed** ثم **Any alert() function call**؛ ليس Price/Crossing.
4. Notifications: فعّل Webhook URL، والصق `https://wetagold.vercel.app/api/tradingview/ingest`. اترك رسالة السكريبت كما يولدها؛ لا تضع كلمة مرور أو توكن MT5/Telegram/Supabase. اختر تشغيلًا مستمرًا وجدول24/7 إن كان متاحًا، وراجع وقت انتهاء التنبيه.
5. اضغط Create. أول إغلاق دقيقة يرسل حزمة. لا يستطيع الموقع إنشاء التنبيه داخل حسابك نيابة عنك أو التحقق من ترجمة Pine دون تشغيله هناك. لا يُدّعى اتصال حي حتى يُرصد وصول أول حزمة صحيحة.

TradingView يشغّل نسخة محفوظة من السكريبت ومدخلاته عند إنشاء التنبيه؛ لو غيّرت السكريبت أو مفتاحه، أعد إنشاء التنبيه. التنبيهات تتطلب التحقق بخطوتين، وطلبات webhook التي تستغرق أكثر3 ثوانٍ قد تُلغى؛ لذلك المستقبل يتحقق ويحفظ فقط، والتحليل والإرسال يتمان في الوظيفة المجدولة المستقلة.

مراجع رسمية راجعت عند التنفيذ: [Webhooks](https://www.tradingview.com/support/solutions/43000529348-how-to-configure-webhook-alerts/)، [دورة التنبيهات والنسخة المحفوظة](https://www.tradingview.com/pine-script-docs/faq/alerts/)، [alert() عند إغلاق الشمعة](https://www.tradingview.com/pine-script-docs/concepts/alerts/).

## ما يصل ومتى يعمل

إرسال واحد لكل دقيقة مكتملة، لا كل tick. الحزمة تحتوي آخر3 شموع ومجموعة40 من التاريخ الحقيقي تدور كل12 دقيقة، لإكمال وتهيئة آخر8 ساعات وإصلاح الرسائل المفقودة. غالبًا تحتاج التهيئة الأولية عدة دقائق، ولا تبدأ إشارات دون21 شمعة M15 مكتملة وآخر240 دقيقة متصلة، ولا تُملأ فجوات. لا تعتمد البوابة على قراءة iframe أو scraping أو Gold API. لا تتحول بيانات عيّنة أو اختبار إلى صفقات إنتاج.

كل حزمة تحمل زمن إغلاق الدقيقة وسعر إغلاقها وOHLC الأصلية؛ تُرفض إذا تأخرت أكثر90 ثانية أو احتوت شمعة حالية مفتوحة أو مستقبلية. تكرار webhook لا يكرر صفقة أو هدفًا، والإرسال الأقدم لا يرجع السعر إلى الوراء. تُحفظ شموع TradingView في جدول مستقل عن شموع MT5. لا يركب المحرك تاريخ مصدرين داخل مؤشرات أو شموع واحدة.

## سياسة الاختيار والمتابعة

MT5 ذو السعر الحديث هو الخيار الأول للصفقات الجديدة؛ إذا انقطع، يُفحص TradingView. إشارة جاهزة تتطلب نفس EMA8/21 واتجاه M15 والدعم/المقاومة بثلاثة ارتدادات ±5$ خلال4 ساعات وشمعة الابتلاع أو الرفض في آخر شمعتين. لا يُعاد شرط اختراق20 دقيقة. الوقف الأبعد3$ والأهداف والحصص وإيقاف النسبة التراكمية كما كانت.

الصفقة المفتوحة تُثبت على مصدرها حتى تنتهي؛ رجوع MT5 لا يحوّل صفقة TradingView إلى أسعار الوسيط، وانقطاع MT5 لا يسمح بحسم أهداف صفقة MT5 من سعر OANDA المختلف. حين يكون المصدران قديمين لا تُصدر إشارة بديلة. فجوة متابعة الصفقة لا تتحول إلى ربح أو خسارة مفترضة؛ حالتها الداخلية قد تصبح غير محسومة، لكن تيليجرام يظل يرسل الدخول ثم الأهداف والوقف فقط.

TradingView سعر **مرجعي لإغلاق الدقيقة**، وليس Bid/Ask. دخول ومتابعة صفقاته من هذا المرجع مع التصريح به في السجل؛ لا يُخترع spread. أعلى/أقل الشمعة لا يحسم ترتيب لمس TP وSL داخل الدقيقة؛ المتابعة تسجل عبور الإغلاق المرصود فقط وقد تفوت حركة داخلها. لا يُدّعى تنفيذ فعلي. تبقى xtele وحواجز الوسيط الخاصة به مستقلة.
