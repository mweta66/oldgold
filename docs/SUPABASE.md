# إعداد Supabase لـ WetaGold

## 1. إنشاء المشروع

أنشئ مشروعًا من حسابك في Supabase، واختر المنطقة والخطة واحفظ كلمة قاعدة البيانات في مدير كلمات مرور. إنشاء المشروع واختيار مؤسسة الحساب والفوترة تحتاج وصول صاحب الحساب؛ المستودع لا ينشئ حسابًا خارجيًا تلقائيًا.

في SQL Editor شغّل migrations `001_wetagold.sql` ثم `002_trade_history.sql` ثم `003_telegram_events.sql` بالترتيب. طبّق غير المطبق فقط ولا تمسح الجداول أو تعيد التهيئة. لا تحتوي الملفات بيانات تجريبية أو بريد مدير أو أسرار. تنشئ الجداول والدوال مع RLS وصلاحيات server-only؛ لا تضف سياسات قراءة مباشرة للمتصفح. عند ترقية مشروع يعمل ببوت حي، أوقف مهام الإرسال والنشر مؤقتًا ثم طبّق 003 وانشر كودها واستأنف الجدولة؛ لا تشغّل عامل الكود القديم على الطابور الجديد.

الترقية 002 تضيف سجلًا كاملًا بصفحات، وتوقيت الفتح والإغلاق عند تغير الحالة، وتستعيد التوقيت القديم من audit إن كان موجودًا فقط. لا تحول أسعار الشارت إلى صفقات ولا تستورد سجل MT5/Bybit. ظهور `SUPABASE_SCHEMA_MISSING` عند تحميل السجل يستدعي تطبيق migration الناقصة، لا إضافة بيانات وهمية.

من إعدادات Auth أوقف السماح بالتسجيل العام، وأبقِ تسجيل البريد/كلمة المرور متاحًا. الموقع ينشئ الحسابات من Auth Admin API ويؤكد البريد إداريًا، وليس بإثبات ملكية بريد المشترك. حساب Auth دون ملف `wg_profiles` لا يدخل الموقع. إعدادات معدل المحاولات وسياسة كلمات المرور في Supabase تظل سارية.

## 2. متغيرات Vercel

| المتغير                     | الاستخدام                                              |
| --------------------------- | ------------------------------------------------------ |
| `SUPABASE_URL`              | Project URL بصيغة HTTPS دون مسار                       |
| `SUPABASE_ANON_KEY`         | مفتاح anon أو publishable key لتسجيل الدخول من الخادم  |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح service_role أو secret key؛ خادم فقط ويتجاوز RLS |
| `PUBLIC_ORIGIN`             | أصل الموقع النهائي مثل `https://example.com` دون مسار  |
| `COOKIE_SECURE`             | `true` في الإنتاج                                      |
| `TELEGRAM_BOT_TOKEN`        | اختياري، توكن البوت                                    |
| `TELEGRAM_GROUP_CHAT_ID`    | رقم جروب الإشارات الخاص، عضويته بإدارة المالك يدويًا   |
| `TELEGRAM_WEBHOOK_SECRET`   | سر عشوائي 32 حرفًا أو أكثر، حروف/أرقام/`_`/`-`         |
| `CRON_SECRET`               | سر عشوائي مستقل لحماية مهمة إعادة الإرسال              |

كلها متغيرات خادم. لا تضف بادئات `VITE_` أو `NEXT_PUBLIC_` أو تضع المفاتيح في ملفات الواجهة. لا تلصق أسرارًا في المحادثة أو Git أو الصور. كلمة المدير تستخدم محليًا للتهيئة فقط، ولا توضع في Vercel. لا يحتاج النشر `BACKEND_ORIGIN`. أعد النشر بعد ضبط المتغيرات.

لا توجه معاينات فروع غير موثوقة إلى مفاتيح إنتاج. استخدم مشروع اختبار ومفاتيحه و`PUBLIC_ORIGIN` المطابق للمعاينة. حماية Vercel SSO تحتاج credentials للـ manifest وقد تمنع webhooks؛ استخدم الدومين العام النهائي لـ Telegram والجدولة دون إضعاف CSP.

## 3. تهيئة المدير الوحيد

محليًا اعتمد `.env.example`، واضبط مفاتيح مشروعك و`ADMIN_EMAIL` و`ADMIN_PASSWORD` بشكل سري، ثم `npm ci` و`npm run supabase:bootstrap`. الأداة ترفض استبدال مدير موجود وتفرض تغيير كلمة المرور عند أول دخول ثم تسجيل الدخول مجددًا. فهرس قاعدة البيانات يمنع مديرًا ثانيًا حتى مع طلبين متزامنين. لا يمكن ترقية عضو من API.

استخدم كلمة قوية من 12 حرفًا فأكثر. قد ترفض سياسة Auth كلمة مؤقتة ضعيفة حتى لو قبلت الأداة طولها. احذف كلمة التهيئة بعد الإنشاء، ولا تعيد التهيئة لاستبدال كلمة المرور. حساب SQLite السابق لا ينتقل: هذه الخطوة تنشئ حساب Supabase جديدًا. لا تعلن أن البريد يعمل على Vercel قبل اختبار الدخول.

## Telegram والإرسال الدوري

أنشئ البوت بواسطة BotFather وأضف أسراره في Vercel وبيئة محلية موثوقة. بعد النشر شغّل `npm run telegram:webhook`. هذا يستبدل webhook الخاص بالبوت؛ استخدم بوت المشروع وليس بوت خدمة أخرى، ولا تشغل long polling القديم بالتوازي.

من لوحة المدير افحص اتصال البوت وخصوصية الجروب. اربط حساب المدير بالبوت وتأكد أنه مالك الجروب الخاص. أضف البوت مشرفًا للإرسال فقط دون صلاحيات إدارة أعضاء، واقفل دعوة الأعضاء العاديين ولا تنشر روابط دعوة. الجروب يستقبل كل الإشارات وتحديثات TP/SL المسجلة؛ أنت وحدك تضيف وتخرج المشتركين. حصص الموقع وانتهاء الحساب لا تقيّد جروبًا مشتركًا. راجع [دليل الجروب](TELEGRAM.md). الاسم القديم `TELEGRAM_ADMIN_CHAT_ID` بديل متوافق؛ الجديد أولى، واحذف الاثنين لتعطيل إرسال الجروب.

دالة النشر تعالج أول دفعة حتى 20 وجهة فورًا. طابور PostgreSQL دائم والـ leases تمنع عاملين من أخذ الرسالة في الوقت نفسه. **مهمة كل دقيقة لازمة لبقية الدفعات وإعادة المحاولات**؛ إضافة متغير السر لا تسجل المهمة تلقائيًا. راقب الحمل وحدود إرسال Telegram عند التوسع.

الخيار الموصى به: فعّل **Cron (pg_cron)** و**pg_net** من لوحة Supabase، ثم احفظ سرين في **Vault**:

- `wetagold_site_origin`: أصل دومين الإنتاج HTTPS.
- `wetagold_cron_secret`: نفس قيمة `CRON_SECRET` في Vercel.

لا تحفظ القيم في SQL داخل Git. بعد حفظها شغّل [supabase/telegram-cron.sql](../supabase/telegram-cron.sql) مرة واحدة. راجع مهمة `wetagold-telegram` وردود `net._http_response`: يرجع `/api/jobs/telegram` استجابة 200 مع Authorization صحيح و401 بدونه. لا تشارك سجلات تحتوي معلومات داخلية. بديلًا، استخدم scheduler موثوقًا يرسل `GET /api/jobs/telegram` مع `Authorization: Bearer <CRON_SECRET>`.

المحاولات تدريجية حتى خمس مرات، بعدها يتدخل المدير. فك الربط أو إيقاف المستخدم يلغي رسائله الخاصة المعلقة، ولا يدير عضويته بالجروب. النشر القديم لا يرسل بعد صلاحية دخوله؛ تحديث TP/SL يظل قابلًا للإرسال 24 ساعة من تسجيله ولا يلغى لمجرد انتهاء وقت الدخول. الطابور يحافظ على ترتيب المحادثة بلقطة كل حدث؛ فشل قديم ثم إعادة محاولة لا يعيد حدثًا أقدم من تحديث وصل بالفعل. قد تتكرر رسالة إذا نجح Telegram ثم انقطع الرد؛ رقم الإشارة/الحدث يميزها. لا يعني فحص getMe نجاح الجروب أو رصد الأهداف من السوق؛ اختبر إرسالًا حقيقيًا في بيئة اختبار.

## 4. فحص القبول

1. `/api/health` يرجع `ok:true` و`provider:"supabase"` و`release` (SHA صالح من متغير Vercel النظامي أو null). يفحص قراءة الجداول وأعمدتها المطلوبة في migrations 001–003 وسجل الإعدادات. 503 يعني نقص الإعدادات/قاعدة غير جاهزة؛ تعديل CSP لا يصلحه. لا يثبت الفحص عقود RPC أو نجاح دخول مستخدم أو تشغيل Cron أو وصول Telegram. تشخيص المدير يعطي فحوصًا إضافية دون كشف بيانات خاصة للعامة.
2. `/api/me` دون جلسة يرجع `user: null` والإشارات والإدارة 401. غيّر كلمة المدير المؤقتة وتحقق من إلغاء جلساته القديمة.
3. أنشئ مشترك اختبار بحصة 1 وتفعيل قريب؛ لا يظهر له المدير ولا يستطيع استدعاء مساراته (403).
4. راجع إشارة اختبار في مشروع **اختبار فقط**: الخصم مرة واحدة والمستلم صاحب الحصة فقط. لا تنشر أسعار اختبار للمشتركين الحقيقيين.
5. جرّب الثيمات والموبايل وإعادة تحميل الصفحة والخروج. الثيم مشترك ومحفوظ، ويتحدث في الصفحات المفتوحة خلال 30 ثانية.
6. اختبر بوت اختبار وربط حساب ورسالة وفشلًا مؤقتًا وإعادة محاولة. راجع نسخ Supabase حسب الخطة وخطة الاستعادة ومراقبة الطابور.

الشارت يظل TradingView `OANDA:XAUUSD` وليس API أسعار. هذه الخطوات لا تثبت أداء استراتيجية أو ربط تنفيذ MT5/Bybit.
