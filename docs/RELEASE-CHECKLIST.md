# بوابات إصدار WetaGold

هذه قائمة قبول، وليست إعلان اكتمال. لا يُنشأ PR جديد أو يُعلن الإصدار جاهزًا بمجرد نجاح الاختبارات المحلية. تبقى الإصلاحات على الفرع الحالي حتى حسم العوائق.

## إصلاحات كود منفذة في الجولة الحالية

- الحفاظ على اختيار حالة الصفقة وقفل العملية الجارية عبر التحديث، وتجنب رسم بطاقات لم تتغير.
- الاحتفاظ بصفحة السجل المطابقة عند عطل مؤقت مع علامة قدم البيانات؛ لا خلط مع فلاتر أو حساب آخر ولا إعلان مزامنة مكتملة عند الفشل الجزئي.
- تمييز وقت فتح الإشارة المسجّل عن تنفيذ الوسيط، وتصدير الصفحة المعروضة CSV بوقتي UTC والمحلي مع حماية صيغ الجداول.
- صفحات حسابات خادمية وبحث حرفي بالبريد وعدد مطابق، بما يتجاوز 1000 حساب دون قطع صامت للقائمة.
- فحص جداول الخدمة والأعمدة المطلوبة، وتشخيص للمدير دون كشف الأسرار، ورقم نسخة الخادم إن توفر من متغير نظام صالح.
- إعادة محاولات Telegram وفق مهلة المزود، واختبارات تمنع إظهار أخطاء المزود الخاصة أو المحاولة المبكرة.
- رفض استجابات HTTP 200 غير مكتملة للإشارات والسجل والإدارة بدل إفساد الجلسة والبيانات السابقة.

لا تتطلب هذه التغييرات migration جديدة ولا إعادة إنشاء الحسابات أو تغيير كلمات المرور.

## عوائق تشغيل لم تُحسم

1. مصدر أسعار حقيقي متاح ومناسب للأداة المطلوبة وحقوق الاستخدام للمشتركين، دون خلط Bybit MT5 بعقد دائم أو OANDA. لا يوجد حل مثبت مجاني ومستمر الآن؛ لا تجاوز لحظر البلد أو WAF، ولا اشتراك مدفوع مفعل.
2. إثبات استراتيجية موثقة خارج العينة ثم محرك دائم لتوليد القرارات وتتبع الدخول وTP/SL من نفس المصدر مع توقف آمن عند انقطاع البيانات. لا توجد مطالبة باستراتيجية مربحة أو بأن أفضل الكورسات دُرست.
3. تقرير 48 ساعة على بيانات فعلية بإعادة تشغيل قواعد ثابتة وتكاليف معلنة؛ يبقى منفصلًا عن سجل الرسائل التي أُرسلت حقيقة، ولا يُعرض على أنه تأكيد تنفيذ أو دليل وصول Telegram.
4. اختبار حي مصرح به للبوت والجروب الخاص والملكية والصلاحيات والجدولة دون نشر إشارات اختبار للمشتركين. Bot API لا ينشئ مجموعة من حساب المالك الشخصي. الإضافة والإخراج يدويان عند المالك حسب الطلب.
5. مقارنة SHA الإنتاج بالنسخة المراجعة ثم اختبار دخول على الموقع العام بحساب اختبار مناسب. نجاح Preview أو health وحده لا يكفي؛ لا دمج أو نشر إنتاج تلقائي في هذه الجولة.

## تحسينات إضافية غير منفذة وليست جاهزة بالتوثيق

- TP1/TP2/TP3 والخروج الجزئي: المخطط الحالي هدف واحد. تحتاج تصميم حالة وقاعدة بيانات وترقية آمنة واختبارات؛ لا تُستنتج من نص رسالة «كل هدف».
- MFA واستعادة المدير: تحتاج رحلة تسجيل عامل يملكها المدير وأكواد استعادة واختبارات منع تجاوز وحماية من قفل الحساب. لا تفعيل بلا تسجيل العامل من المالك ولا اعتماد على إخفاء الواجهة.
- نسخ Supabase واستعادة حقيقية: يلزم التحقق من إمكانات الخطة، واختبار في مشروع استعادة منفصل، وعدم مس بيانات الإنتاج. اختبارات SQLite ليست إثبات استعادة Supabase.
- سياسة مخاطرة: الإشارات لا تتحكم في حساب الوسيط؛ حد 10% لا يمكن ضمانه من الموقع. لا تُفعّل سياسة يومية أو تراجع من قمة الأرباح من دون تحديد معناها، ولا تُحوّلها إلى ادعاء حماية رأس المال.
- تشغيل واسع: اختبار تأخر الطابور ومهلة الدالة وحدود خطط Vercel وSupabase وحدود رسائل Telegram، واختبار Safari حقيقي. لا ضمان مجاني غير محدود أو exactly-once.
- تدوير أي مفاتيح سبق كشفها: يتم من حساب مالك الخدمة مع تحديث الأسرار المعتمدة واختبار الربط. لا تُعاد قراءة مفاتيح المحادثة أو نشرها، ولا يُلغى مفتاح حي دون خطة تمنع قطع الخدمة.

## تحقق قبل أي إصدار

نفذ `npm run check` و`npm test` و`npm run test:browser` و`npm run build:static` و`npm run format:check` و`git diff --check`، ثم راجع الأدلة الحية أعلاه. اختبارات السوق وTelegram تستخدم حدود مزود محاكية ولا تعوّض التحقق الحي.
