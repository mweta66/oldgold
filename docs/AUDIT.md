# مراجعة WetaGold

## التغييرات الحالية

| المشكلة                                  | الإصلاح                                                      | التحقق                                                      |
| ---------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| Vercel بلا Backend دائم؛ الدخول يرجع 503 | API مباشر إلى Supabase وفحص جاهزية واضح                      | SDK حقيقي مع شبكة محاكية؛ 503 للإعداد الناقص                |
| manifest يتحول إلى SSO بالمعاينة         | credentials لنفس المصدر و`manifest-src 'self'`               | Chromium بكوكي معاينة اختباري                               |
| غياب الهوية واللوجو                      | لوجو WG ذهبي شفاف وعلامة مائية وCairo محلي                   | صور الموبايل والكمبيوتر وفحص تحميل الخط والصورة             |
| ألوان ثابتة                              | أربعة ثيمات محفوظة، تعديل للمدير فقط، منها فاتح              | API وصلاحيات SQL ومتصفح وتباين WCAG                         |
| حسابات وحصص محلية لا تناسب Vercel        | Supabase Auth وملفات أعضاء وجلسات PostgreSQL خاصة            | migration فعلي على PostgreSQL عبر PGlite                    |
| خطر الخصم المتكرر وكشف البيانات          | تخصيص ذري وrequestId فريد وحصة وتفعيل وفحص دور               | اختبارات SQL وعزل الأعضاء ومنع أدوار المتصفح من الجداول/RPC |
| عامل Telegram دائم لا يناسب serverless   | webhook محمي وoutbox بـ leases وإرسال عند النشر وجدولة محمية | SQL وSDK ومزود Telegram محاكى، ودليل Vault/Cron             |

تبقى جلسات HttpOnly وCSRF وOrigin وإجبار تغيير كلمة تهيئة المدير قبل فتح الصلاحيات. لا توجد أسعار أو حسابات إنتاج أو أسرار مضمّنة. اختبارات SQLite القديمة تمنع التراجع في وضع التطوير ولا تثبت نشره على Vercel.

## ما لم يكتمل خارجيًا

أضيفت migration `003_telegram_events.sql` لأحداث نشر وحالات مستقلة مع لقطات ثابتة وترتيب لكل محادثة. إشعار TP/SL لا يلغى بسبب انتهاء وقت الدخول، وتحديثات الحالات لا تخصم حصة. فحص الجروب يمنع الإرسال عند رصد اسم عام أو دعوات أعضاء أو مالك غير مطابق أو صلاحيات عضوية للبوت. لا يضيف أو يحذف البوت مشتركين؛ الجروب مشترك لكل إشاراته، فالحصص وانتهاء الحساب تنطبق على الموقع والرسائل الخاصة فقط، وإدارة عضوية الجروب للمالك يدويًا. الفحص قراءة معلومات، وليس إنشاء جروب أو تغيير إعداداته نيابة عن صاحب حساب Telegram.

أضيف سجل صفقات مستقل لكل تاريخ الحساب بصفحات من 20، وفلاتر UTC/الحالة/الاتجاه وتواريخ واضحة للنشر والفتح والإغلاق. أزيل خلط آخر صفقة مغلقة بالإشارات الحالية، والإشارة المفتوحة القديمة لا تخفى بسبب نافذة 90 يومًا. يلزم تطبيق `002_trade_history.sql` على المشروع المتصل؛ الاختبارات لا تنشئ سجلات إنتاج أو تستورد صفقات وسيط. أوقات تاريخية مفقودة لا يتم تخمينها، وفشل جلب السجل يظهر كخطأ لا كسجل فارغ.

- لا يتوفر وصول لحساب Supabase أو مشروع جاهز؛ لم يُنشأ مشروع حي أو تطبق migration عليه. يلزم إنشاء المشروع وإضافة المفاتيح إلى Vercel وإعادة النشر وتهيئة المدير. الكود وحده لا يصلح نشرًا قديمًا لم يتغير.
- لم ينشأ بوت/جروب أو تسجل جدولة في حساب المستخدم. التجهيز يشمل دليل الجروب الخاص وفحصه وVault/Cron. الاختبارات لا ترسل رسائل حقيقية. لا يوجد اكتشاف آلي لتحقق TP/SL من سعر السوق؛ الإرسال تلقائي لما يسجله الموقع فقط.
- حساب SQLite السابق محلي ولا ينتقل إلى Supabase Auth تلقائيًا. لا يوجد بريد أو كلمة مرور افتراضية منشورة.
- النسخ والاستعادة تعتمد خطة Supabase وإعدادات المشروع. لا ضمان لنسخ يومية مجانية أو استعادة خارجية اختبرت بالفعل.
- الاختبارات تشغل PostgreSQL مدمجًا وSDK حقيقيًا بحد شبكة محاكى؛ لا تختبر حمل PostgreSQL متعدد الاتصالات أو توفر المزودين الحي.

## التحسينات التالية

1. **مصدر سعر مرخص:** الشارت فعلي لكن إدخال المستويات يدوي. التحقق من حداثة رقم ليس إثبات مطابقته للسوق؛ لا تخلط OANDA بسعر Bybit.
2. **إثبات استراتيجية:** لا يوجد AI مدرب أو تنفيذ MT5. وثّق القواعد واختبر خارج العينة مع السبريد والانزلاق. الإشارات وحدها لا تفرض حد خسارة 10% على حساب الوسيط.
3. **التشغيل:** راقب health والـ Cron والطابور وفشل المهام والنسخ والاستعادة. الإرسال الفوري حتى 20 وجهة ثم تستكمل الجدولة.
4. **حساب المدير:** MFA واستعادة موثقة وتسجيل محاولات الدخول وتنبيهات أمنية. تأكيد البريد عند الإنشاء إداري وليس إثبات ملكية المشترك لبريده.
5. **التحديثات:** استبدال polling بتحديثات آمنة عند الحاجة وترقيم صفحات السجلات الكبيرة؛ لا تخزن بيانات خاصة دون اتصال في PWA.
