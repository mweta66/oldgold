# مراجعة Xgold

## مراجعة الإصدار الحالية — 21 أكتوبر 2026

### متابعة التنفيذ: TP1/TP2/TP3 — تحتاج ترقية 004 قبل الإنتاج

أضيفت أهداف مرتبة من 1–3 مع تقدّم محفوظ، ومسار مدير ذري/idempotent لتسجيل الهدف التالي، وحدث Telegram مستقل لكل هدف متعدد دون خصم حصة جديدة. TP1/TP2 لا يغلقان الإشارة إلا إذا كان أحدهما آخر هدف؛ الوقف بعد تقدم جزئي يحفظه ولا يدّعي حساب ربح فعلي أو تنفيذ إغلاق جزئي. بطاقات المشترك والسجل وCSV تعرض المستويات والتقدم دون شارت. قفل العملية ومسودة الحالة يظلان محفوظين أثناء التحديث.

ترقية PostgreSQL الحقيقية 004 اختُبرت على PGlite من مخطط 001–003 بصفقات وطابور قائمين؛ لم تغيّر لقطاتهما أو حالاتهما أو الحصص، ولم تُنشئ تنبيهات تاريخية جديدة. اختُبر منع تخطي الأهداف وتغيير مستوياتها، وتكرار الطلب والصلاحيات ولقطات كل تقدم والإغلاق النهائي. اختبارات Telegram بمزود محاكى تثبت نصوص المجموعة والمشترك وترتيبها دون خصم/إرسال إضافي عند التكرار. فحص health يتطلب الأعمدة الجديدة وأداة تفعيل السحابة ترفض مخططًا موجودًا بلا دالة/أعمدة الأهداف بدل ترقية صامتة. راجع [خطة الترقية ووقف العمال](MULTIPLE-TARGETS.md).

لم تُطبّق 004 على إنتاج Supabase ولم يُنشر إصدار الإنتاج أو تُنشأ مجموعة Telegram. لا يزال توليد الإشارات وتتبع الأهداف من السعر الحي وتقرير آخر 48 ساعة الحقيقي غير مفعّل؛ دعم تسجيل أهداف متعددة لا يحل مصدر البيانات أو يثبت أداء الاستراتيجية. MFA واستعادة Supabase والتحقق الحي تبقى في بوابات الإصدار.

### جولة إصلاح ثانية بطلب المالك — غير منشورة للإنتاج

أعيد إنتاج ثلاثة أخطاء لم تكن تغطيها المجموعة السابقة: إعادة اختيار حالة الإشارة إلى الافتراضي بعد التحديث، اختفاء صفحة السجل عند عطل مؤقت، وتغيير توقيت آخر مزامنة رغم فشل السجل. عولجت بحالة مستقلة لمسودة الحالة وقفل الطلب الجاري عبر إعادة الرسم، وحفظ الصفحة المطابقة فقط مع تنبيه واضح لقدمها، وإشارة تحديث جزئي دون تغيير توقيت آخر مزامنة مكتملة. الاستجابات الناجحة شكليًا لكن ناقصة محتوى الإشارات/السجل/الإدارة تُرفض كأخطاء خدمة دون إفساد الجلسة. لا يختلط فشل الشبكة بخروج حقيقي أو انعدام صفقات.

أضيفت صفحات خادمية للحسابات من 20 مع عدّ وبحث حرفي (اختبار يتجاوز 1000 حساب)، وتصدير CSV للصفحة المعروضة مع UTC والتوقيت المحلي وحماية صيغ الجداول. أصبح وقت فتح الإشارة «مسجّلًا» لا ادعاء تنفيذ وسيط. فحص health يتحقق من الجداول وأعمدة migrations المطلوبة، وتشخيص للمدير يقرأ حالة المخطط وواجهة إدارة Auth ويعرض رقم نسخة الخادم إن توفر وحالات الطابور دون وجهات أو أسرار. لا ينفّذ تشخيص الإدارة تغييرات أو يرسل صفقات اختبار أو يستنتج تشغيل السوق/Cron من وجود الإعدادات.

عولجت إعادة محاولات Telegram وفق `retry_after` الموثوق مع حفظ الموعد في الطابور، واختبارات SQLite وSupabase SDK تمنع المحاولة المبكرة. لا زيادة غير مختبرة لحد الدفعة أو ادعاء exactly-once. طلبات SDK لها مهلة 8 ثوان لكل طلب؛ رحلة API قد تتضمن أكثر من طلب.

تشغيل [فحص الخدمات 39660211360](https://github.com/mweta66/oldgold/actions/runs/39660211360) الجديد انتهى بنجاح على main كفحص قراءة فقط، لكن تحميل سجل النتائج التفصيلي رُفض من الشبكة؛ لا تُستنتج منه صحة مزود بعينه أو النشر أو وصول الجروب. لم يُستخدم مصدر بديل لتجاوز المنع ولم تُنقل الأسرار إلى جلسة التطوير. نتائج الفحص الأقدم أدناه مؤرخة ولا تعني تحققًا حيًا جديدًا.

في الجولة الثانية لم تُنفّذ السوق الآلية أو تقرير 48 ساعة الحقيقي أو تعدد الأهداف أو MFA أو استعادة Supabase أو التحقق الحي، ولم تتضمن تغييرات SQL أو إنشاء حسابات إنتاج أو دمج/نشر إنتاج. أضيف دعم الأهداف لاحقًا كما في فقرة المتابعة أعلاه؛ الحدود الحالية في [بوابات الإصدار](RELEASE-CHECKLIST.md).

تعديل العرض حسب طلب المالك: نُقل شارت TradingView إلى قسم الإدارة وحده، مع إخفاء افتراضي وحارس دور المدير قبل إنشاء iframe أو تشغيل أزرار الفريم والتكبير. المشترك والزائر لا يحمّلان الشارت، حتى بعد إعادة التحميل وتغيير الحساب والتوقيت؛ لوحة المشترك تعرض الإشارات وآخر صفقة والسجل بعرض كامل. اختبار المتصفح لمسار Supabase يتحقق من عدم وجود iframe وعدم صدور طلبات TradingView للمشترك، بما في ذلك نقر عناصر الشارت المخفية برمجيًا.

الإرسال إلى Telegram لا يتضمن صور شارت؛ الاختبارات تتحقق من نشر الإشارة وتحديثاتها النصية للجروب الخاص وللمستلم المستحق، دون خصم حصة ثانية لتحديث الحالة. هذا إثبات كود بحد مزود محاكى وليس اختبار وصول إلى الجروب الحقيقي. نشر الإشارات وتسجيل الهدف/الوقف ما زالا إداريين؛ إخفاء الشارت عن الأعضاء لا يفعّل محرك سوق ولا يتجاوز قيود الوصول أو شروط استخدام البيانات لإنتاج إشارات لهم.

المراجعة تشمل الواجهة والموبايل، الدخول والجلسات وتبديل الحساب، حماية المسارات والصلاحيات، الحصص وسجل الصفقات والتوقيت، طابور Telegram وفحص الجروب، وحدود مختبر Bybit ومسار النشر. ليست ضمانًا لعدم وجود أخطاء، ولا اختبار أداء تداول.

### العيوب المثبتة التي أُصلحت

- رفض رابط نشر Vercel مع اختلاف `PUBLIC_ORIGIN`: قبول عناوين النشر الدقيقة من متغيرات Vercel، دون السماح العام لنطاقاتها أو الثقة بترويسات Host.
- وصول نجاح عملية قديمة بعد تسجيل الخروج/الدخول: حواجز جيل الجلسة تمنع إخراج الحساب الجديد، أو مسح نموذجه، أو عرض رابط Telegram يخص الجلسة السابقة. تُمسح حالة الأزرار والنماذج عند تبديل الجلسة.
- استجابة JSON غير صالحة أو جلسة بلا حقل user كانت قد تبدو كخروج حقيقي: تُعامل كخطأ خدمة مع إبقاء الجلسة والبيانات السابقة. لا يزال `user:null` الصريح أو 401 الحقيقي ينهي الجلسة.
- تحديث لوحة الإدارة أثناء نشر إشارة كان يعيد تفعيل زر النشر: حارس طلب جارٍ وقفل حقول النموذج يمنعان التكرار وتعديل المسودة أثناء إرسالها. يبقى requestId ثابتًا لإعادة المحاولة، وقيد التكرار في قاعدة البيانات قائمًا.
- فحص الجروب كان يراجع الدعوات لا إرسال الأعضاء: يرفض الآن صلاحيات الرسائل والوسائط والاستفتاءات والروابط وإدارة المجموعة للأعضاء العاديين، دون محاولة تغيير إعداداتهم أو إدارة العضوية.
- تعطل Auth عند التحقق من كلمة المرور كان يظهر ككلمة مرور خاطئة: تمييز 503 وحد المحاولات 429 عن أخطاء الإدخال، دون إلغاء الجلسة القائمة بسبب عطل المزود.
- بعض ملفات JavaScript لم تدخل في فحص الصياغة: فحص جميع ملفات التطبيق والاختبارات والسكربتات، وإضافة فحص التنسيق إلى CI.

### أدلة التحقق وحدودها

اختبارات الوحدات والتكامل تنفّذ SQL الحقيقي على PostgreSQL مدمج وتستخدم Supabase SDK الحقيقي مع محاكاة حد الشبكة، لا مفاتيح أو بيانات إنتاج. أضيف اختبار متصفح HTTPS بعناوين Vercel، Secure/HttpOnly cookies، تسجيل الدخول وإعادة التحميل والخروج كمدير ومشترك، والتحقق من عزل الصلاحيات. اختبارات السباق تؤخر رد تغيير كلمة المرور وربط Telegram وحفظ الحساب ثم تبدّل الجلسة، وتثبت عدم تأثير الردود القديمة عليها. تشمل الاختبارات البصرية قابلية الوصول والثيمات وCairo والموبايل، لكن Chromium لا يثبت التوافق مع Safari الفعلي أو كل الأجهزة.

فحص `npm audit --omit=dev` لم يجد ثغرات معلنة في مكتبات الإنتاج وقت هذه المراجعة؛ هذا ليس فحص اختراق كاملًا. فحوصات GitHub السابقة نجحت، وتشغيل readiness الجديد قراءة فقط للخدمات الموجودة ولا ينشر صفقات أو يغير المستخدمين. نجاح وصول API أو health لا يثبت نجاح دخول المدير من جهازه أو اكتمال كل خصائص التداول.

نتيجة [فحص الخدمات 39632466885](https://github.com/mweta66/oldgold/actions/runs/39632466885): نجحت مصادقة واجهات إدارة Supabase وVercel والبوت، ومشروع Supabase سليم، وhealth للموقع العام رجع 200، ونشر الإنتاج وُصف READY. هذه النتيجة لا تختبر دخول المستخدم أو Bybit. قيمة `TELEGRAM_GROUP_CHAT_ID` غير مضافة بحسب فحص **وجود الأسماء فقط**، لكن الفحص لا يتحقق من الاسم القديم `TELEGRAM_ADMIN_CHAT_ID`؛ لا يمكن الجزم بأن كلاهما غائب. تعذر طلب معلومات webhook في هذا التشغيل، لذلك حالته غير محسومة، وليست «غير موجودة» مؤكدًا. جاهزية المنتج الكاملة ظلت false.

بعد إضافة الأهداف نجح محليًا 105 اختبارات وحدة/تكامل و20 اختبار متصفح، وفحص 55 ملف JavaScript والبناء والتنسيق. تُعاد المجموعة بعد تعديل الكود قبل تسليم الإصدار. لم تُنفَّذ هذه الاختبارات بحسابات الإنتاج أو توكنات من المحادثة.

### عوائق تمنع وصف المنتج بأنه جاهز بالكامل

1. إصلاحات PR #10 تحتاج دمجًا ونشرًا؛ الفرع لا يغيّر الموقع العام تلقائيًا قبل الدمج. يلزم التحقق من نشر نفس SHA ثم اختبار رحلة دخول إنتاج مع حساب اختبار مخصص وموافقة على استخدامه، لا تجربة أسعار على المشتركين.
2. آخر اختبار مباشر لواجهة Bybit من بيئة العمل أعاد 403 برسالة حظر البلد. لا يوجد تجاوز للحظر، ولم يتم التحقق من عقد ذهب مطابق أو نتائج سوق حقيقية لآخر 48 ساعة. المختبر يرفض الفشل ولا يخترع نتائج.
3. قواعد M15/M1 بحثية غير مثبتة؛ التوليد والنشر ومتابعة TP/SL من السوق تلقائيًا غير مفعّلة. إشارات الموقع الحالية يدوّنها المدير ومصدر الشارت OANDA، وليس Bybit.
4. عضوية جروب Telegram وملكيته وضبط الصلاحيات بيد المالك. الفحص البرمجي لا ينشئ جروبًا ولا يثبت وصول رسالة فعلية دون اختبار حي مصرح به. الجدولة والنسخ والاستعادة والحمل تعتمد الإعدادات والخطة؛ لم تُشترَ خطة مدفوعة.

تحديث بحث المصدر البديل: نجح نشر إعدادات شبكة البيئة وتأكد تطبيق النطاقات السبعة، ثم نجح الوصول إلى صفحات Dukascopy الرسمية. واجهة الشموع أعادت تحدّي WAF بدون بيانات، والشروط العامة لا تثبت حق الاستخدام المطلوب للمشتركين. لذلك لم يُفعّل المصدر ولا النشر الآلي ولم تُنشأ نتائج تاريخية. راجع [أدلة المصادر البديلة](MARKET-DATA-OPTIONS.md)؛ إعادة طلب Publish ليست حلًا لهذين العائقين.

تبقى جلسات HttpOnly وCSRF وOrigin وإجبار تغيير كلمة تهيئة المدير قبل فتح الصلاحيات. لا توجد أسعار أو حسابات إنتاج أو أسرار مضمّنة. اختبارات SQLite القديمة تمنع التراجع في وضع التطوير ولا تثبت نشره على Vercel.

## ما لم يكتمل خارجيًا

أضيفت migration `003_telegram_events.sql` لأحداث نشر وحالات مستقلة مع لقطات ثابتة وترتيب لكل محادثة. إشعار TP/SL لا يلغى بسبب انتهاء وقت الدخول، وتحديثات الحالات لا تخصم حصة. فحص الجروب يمنع الإرسال عند رصد اسم عام أو دعوات أعضاء أو مالك غير مطابق أو صلاحيات عضوية للبوت. لا يضيف أو يحذف البوت مشتركين؛ الجروب مشترك لكل إشاراته، فالحصص وانتهاء الحساب تنطبق على الموقع والرسائل الخاصة فقط، وإدارة عضوية الجروب للمالك يدويًا. الفحص قراءة معلومات، وليس إنشاء جروب أو تغيير إعداداته نيابة عن صاحب حساب Telegram.

أضيف سجل صفقات مستقل لكل تاريخ الحساب بصفحات من 20، وفلاتر UTC/الحالة/الاتجاه وتواريخ واضحة للنشر والفتح والإغلاق. أزيل خلط آخر صفقة مغلقة بالإشارات الحالية، والإشارة المفتوحة القديمة لا تخفى بسبب نافذة 90 يومًا. يلزم تطبيق `002_trade_history.sql` على المشروع المتصل؛ الاختبارات لا تنشئ سجلات إنتاج أو تستورد صفقات وسيط. أوقات تاريخية مفقودة لا يتم تخمينها، وفشل جلب السجل يظهر كخطأ لا كسجل فارغ.

- توثّق [نتائج التفعيل](CLOUD-ACTIVATION.md) تشغيلًا سابقًا جهّز Supabase والنشر وwebhook والجدولة؛ لا يصح تعميم ذلك على صحة كل نشر لاحق. لا تتوفر أسرار الخدمات داخل جلسة العمل الحالية، ويستخدم readiness أسرار GitHub الموجودة للقراءة فقط. لا نعيد إنشاء المشاريع أو المدير أو المخطط كجزء من مراجعة التطوير.
- لم يُثبت في هذه المراجعة إنشاء الجروب الخاص أو جاهزية مالكه وصلاحياته. التجهيز يشمل دليل الجروب وفحصه وVault/Cron. الاختبارات المحلية لا ترسل رسائل حقيقية. لا يوجد اكتشاف آلي لتحقق TP/SL من سعر السوق؛ الإرسال تلقائي لما يسجله الموقع فقط.
- حساب SQLite السابق محلي ولا ينتقل إلى Supabase Auth تلقائيًا. لا يوجد بريد أو كلمة مرور افتراضية منشورة.
- النسخ والاستعادة تعتمد خطة Supabase وإعدادات المشروع. لا ضمان لنسخ يومية مجانية أو استعادة خارجية اختبرت بالفعل.
- الاختبارات تشغل PostgreSQL مدمجًا وSDK حقيقيًا بحد شبكة محاكى؛ لا تختبر حمل PostgreSQL متعدد الاتصالات أو توفر المزودين الحي.

## التحسينات التالية

1. **مصدر سعر مرخص:** الشارت فعلي لكن إدخال المستويات يدوي. التحقق من حداثة رقم ليس إثبات مطابقته للسوق؛ لا تخلط OANDA بسعر Bybit.
2. **إثبات استراتيجية:** لا يوجد AI مدرب أو تنفيذ MT5. وثّق القواعد واختبر خارج العينة مع السبريد والانزلاق. الإشارات وحدها لا تفرض حد خسارة 10% على حساب الوسيط.
3. **التشغيل:** راقب health والـ Cron والطابور وفشل المهام والنسخ والاستعادة. الإرسال الفوري حتى 20 وجهة ثم تستكمل الجدولة.
4. **حساب المدير:** MFA واستعادة موثقة وتسجيل محاولات الدخول وتنبيهات أمنية. تأكيد البريد عند الإنشاء إداري وليس إثبات ملكية المشترك لبريده.
