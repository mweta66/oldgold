## حدود مهمة للنشر الحالي

- النسخة تعتمد نشر المدير للإشارات وتسجيل النتائج؛ لا يوجد محرك استراتيجية يقرأ السعر ويصدر توصيات تلقائيًا. لم تتم دراسة أو اعتماد خمس استراتيجيات أو تدريب فلتر AI بعد.
- لا يمكن استخراج سعر TradingView من iframe كواجهة أسعار مدعومة. المصدر التالي يحتاج مزود بيانات مرخصًا من نفس السوق، مع معالجة bid/ask والانقطاعات وتكاليف التداول.
- Telegram يحتاج توكن صالحًا وإتمام المستخدم Start. الجروب الاختياري للإدارة فقط حتى لا يتجاوز المشتركون الحصص. لم يتم إنشاء جروب أو حساب خارجي أو إرسال رسالة حية أثناء المراجعة.
- اختبارات الشارت تعزل مزود الخدمة الخارجي. حجب الشبكة في بيئة التطوير يمنع اعتبار الشارت أو اتصال Telegram أو GitHub API مختبرًا حيًا.
- لا يعمل الخادم في GitHub Pages وحده. تشغيله يحتاج Node 24 وتخزينًا دائمًا وHTTPS للإنتاج.
- النسخ اليومية على نفس الجهاز ليست بديلًا عن نسخة خارجية. إدارة bot واحدة ونسخة تطبيق واحدة مطلوبة في هذا الإصدار.
- لم يتم نشر حساب مدير بكلمة عامة، ولا يتضمن المستودع أسرار تشغيل. يلزم إنشاء أول مدير بإعدادات الخادم.

## تحسينات مقترحة بالترتيب

1. **توحيد بيانات السوق:** ربط API مرخص لنفس رمز OANDA أو لمصدر التنفيذ المختار، وإظهار وقت آخر tick والتحقق من spread وتقادم البيانات. بعدها يصبح توليد ومتابعة الإشارات تلقائيًا ممكنًا.
2. **إثبات أداء الاستراتيجية:** قواعد قابلة للبرمجة، بيانات tick مناسبة للدقيقة، رسوم وانزلاق، اختبار خارج العينة وتشغيل متابعة. نسبة النجاح وحدها لا تكفي لاختيار نموذج.
3. **تقوية حساب المدير:** إضافة 2FA واستعادة حساب موثقة وتنبيهات أمنية. تسجيل الدخول الحالي آمن بجلسات خادم، لكن 2FA واستعادة البريد غير منفذين.
4. **تشغيل دائم:** استضافة Node بتخزين دائم، مراقبة uptime، نسخ مشفرة خارج الجهاز واختبار استعادة دوري.
5. **تجربة المشترك:** تحديثات SSE بدل polling، تنبيهات متصفح بإذن المستخدم، وفوترة فعلية بعد تحديد وسيلة الدفع والأسعار. Manifest الحالي يتيح فتح الموقع كتطبيق؛ لا يدعي دعم push أو بيانات خاصة دون اتصال.
6. **التوسع عند الحاجة:** قاعدة بيانات وخدمة رسائل مشتركتان قبل تشغيل عدة خوادم. إصدار النظام الحالي مخصص لنسخة خادم واحدة.
