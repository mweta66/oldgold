# التحقق الآمن من حسابات النشر

عندما لا تظهر إعدادات بيئة ChatGPT، يمكن لصاحب المستودع حفظ `SUPABASE_ACCESS_TOKEN` و`VERCEL_TOKEN` و`TELEGRAM_BOT_TOKEN` في **Settings → Secrets and variables → Actions → Repository secrets** في GitHub. هذه الأسرار متاحة لعامل GitHub Actions فقط، وليست اتصالًا بحسابك داخل المحادثة. ألغِ أي توكن نُشر في المحادثة وأدخل بديله هنا، دون لصقه في Git أو الصور.

Workflow **WetaGold cloud readiness** يفحص وجود الأسرار والوصول للواجهات الثلاث **للقراءة فقط**. لا ينشئ مشروع Supabase أو جروب Telegram، لا يطبق migrations، لا يغير متغيرات Vercel أو webhook، ولا يرسل رسائل. نجاحه يثبت اتصال API لا جاهزية الموقع أو صلاحية كل عملية كتابة.

يفحص فقط مشروعات `oldgold`/`wetagold` ويتحقق من ارتباط مشروع Vercel بهذا المستودع، مع تعداد وجود متغيرات الإنتاج دون قيمها. لا ينشر قوائم حساباتك أو استجابات المزود الخام أو محتوى المحادثات. لا يستدعي getUpdates ولا يستهلك تحديثات البوت.

لا يعمل من pull requests أو forks. خطوات الفحص تستخدم إجراءات مثبّتة بـ SHA، وتحقن الأسرار في خطوة الفحص وحدها؛ اختبارات التنقيح لا تحصل عليها. التشغيل الأول على فرع `feature/cloud-readiness` مقصود للتحقق قبل دمج الملف. بعد الدمج يمكن تشغيله يدويًا من **Actions → WetaGold cloud readiness → Run workflow** على `main` فقط. التقرير المنقّح في ملخص التشغيل وnotice لا يحتوي قيمًا سرية، لكنه قد يظهر اسم البوت العام ومعلومات جاهزية مشروع الموقع على مستودع عام.

إذا كان أي سر ناقصًا أو مرفوضًا يفشل التشغيل برسالة ثابتة أو كود HTTP دون تفاصيل حساسة. خزّن البديل بالاسم الصحيح ثم أعد تشغيل المهمة. لا تعِد طلب توكن جديد لمجرد فشل اكتشاف مشروع؛ قد يكون الحساب أو نطاق صلاحية التوكن مختلفًا.

بعد الفحص يلزم إجراء تفعيل منفصل على هدف مؤكد كما في [دليل Supabase](SUPABASE.md) و[دليل Telegram](TELEGRAM.md). اختيار مؤسسة/مشروع ملتبس أو خطة مدفوعة يحتاج تحديدًا من صاحب الحساب؛ لا يجوز التخمين أو مسح مشروع قائم. إنشاء الجروب والبوت من حساب Telegram الشخصي يظل خطوة المالك، ويمكن جعل الجروب للقراءة فقط من صلاحيات الأعضاء.
