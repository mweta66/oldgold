# التحقق الآمن من حسابات النشر

عندما لا تظهر إعدادات بيئة ChatGPT، يمكن لصاحب المستودع حفظ `SUPABASE_ACCESS_TOKEN` و`VERCEL_TOKEN` و`TELEGRAM_BOT_TOKEN` في **Settings → Secrets and variables → Actions → Repository secrets** في GitHub. هذه الأسرار متاحة لعامل GitHub Actions فقط، وليست اتصالًا بحسابك داخل المحادثة. ألغِ أي توكن نُشر في المحادثة وأدخل بديله هنا، دون لصقه في Git أو الصور.

Workflow **Xgold cloud readiness** يفحص وجود الأسرار والوصول للواجهات الثلاث **للقراءة فقط**. لا ينشئ مشروع Supabase أو جروب Telegram، لا يطبق migrations، لا يغير متغيرات Vercel أو webhook، ولا يرسل رسائل. نجاحه يثبت اتصال API لا جاهزية الموقع أو صلاحية كل عملية كتابة.

يفحص فقط مشروعات `oldgold`/`wetagold` ويتحقق من ارتباط مشروع Vercel بهذا المستودع، مع تعداد وجود متغيرات الإنتاج دون قيمها. لا ينشر قوائم حساباتك أو استجابات المزود الخام أو محتوى المحادثات. لا يستدعي getUpdates ولا يستهلك تحديثات البوت.

لا يعمل من push أو pull requests أو forks. خطوات الفحص تستخدم إجراءات مثبّتة بـ SHA، وتحقن الأسرار في خطوة الفحص وحدها؛ اختبارات التنقيح لا تحصل عليها. التشغيل يدوي من **Actions → Xgold cloud readiness → Run workflow** على `main` فقط. أزيل تشغيل فرع الإعداد التلقائي بعد نجاح التفعيل الأول. التقرير المنقّح في ملخص التشغيل وnotice لا يحتوي قيمًا سرية، لكنه قد يظهر اسم البوت العام ومعلومات جاهزية مشروع الموقع على مستودع عام.

إذا كان أي سر ناقصًا أو مرفوضًا يفشل التشغيل برسالة ثابتة أو كود HTTP دون تفاصيل حساسة. خزّن البديل بالاسم الصحيح ثم أعد تشغيل المهمة. لا تعِد طلب توكن جديد لمجرد فشل اكتشاف مشروع؛ قد يكون الحساب أو نطاق صلاحية التوكن مختلفًا.

بعد الفحص يلزم إجراء تفعيل منفصل على هدف مؤكد كما في [دليل Supabase](SUPABASE.md) و[دليل Telegram](TELEGRAM.md). اختيار مؤسسة/مشروع ملتبس أو خطة مدفوعة يحتاج تحديدًا من صاحب الحساب؛ لا يجوز التخمين أو مسح مشروع قائم. إنشاء الجروب والبوت من حساب Telegram الشخصي يظل خطوة المالك، ويمكن جعل الجروب للقراءة فقط من صلاحيات الأعضاء.

## تفعيل الإنتاج بعد تأكيد الأهداف

Workflow **Activate Xgold** إجراء منفصل **يغيّر إعدادات الإنتاج**، وليس مجرد فحص. أضيف لطلب صاحب المشروع تفعيل الموقع بالكامل. التشغيل يدوي فقط من **Actions → Activate Xgold → Run workflow** على `main`؛ لا تعمل المهمة من أي فرع آخر أو push أو pull request. لا تستخدمه في مستودع/حساب آخر دون مراجعة الحواجز.

- يشترط مشروع Supabase وحيدًا مطابق الاسم، ومشروع Vercel وحيدًا مرتبطًا بهذا المستودع، ودومين إنتاج مؤكدًا غير ملتبس. يتوقف إن كان البوت مربوطًا بموقع آخر أو إعداد Supabase الإنتاجي مختلفًا.
- ينشئ مخطط Xgold **فقط إذا لم توجد أي جداول wg_**. يطبق 001–004 في معاملة واحدة، مع checksums خاصة. المخطط القديم الناقص يحتاج مراجعة ترقية منفصلة، ولا يمسحه العامل أو يعيد تهيئته. المخطط المكتمل يفحص RLS وخصوصية الجداول وتوفر دوال الأحداث والسجل ودالة وأعمدة الأهداف المتعددة. وجود 001–003 فقط لا يجيز نشر نسخة تتطلب 004؛ راجع [ترقية الأهداف والعمال](MULTIPLE-TARGETS.md).
- يجلب مفاتيح المشروع إلى ذاكرة العامل فقط، ويخفيها قبل استخدامها. يحفظ مفاتيح الخادم على Vercel للإنتاج وحده، ويثبت `PUBLIC_ORIGIN` وSecure cookies، ويغلق التسجيل العام في Supabase. لا تضاف توكنات إدارة Supabase/Vercel إلى بيئة الموقع.
- ينشئ أسرار webhook وCron في Supabase Vault إذا كانت غير موجودة، ويعيد استخدام الموجودة دون طباعتها. لا يغيّر أصل موقع مختلف مسجل في Vault.
- ينشر **SHA main الذي تم جلبه صراحةً**، لا كود فرع الفحص، ويفحص `/api/health` و`/api/me` ورفض الإشارات للمجهول. لا ينشئ إشارات سوق أو مشتركين اختبار.
- يثبت إطار Vercel على **Other** (`framework: null`) للواجهة الثابتة ودوال `api/`. الإطار الخادمي التلقائي Node قد يختار `app.js` الخاص بالمتصفح كمدخل خادم ويسبب `document is not defined`؛ هذا ما ظهر في الفحص الحي. التثبيت موجود أيضًا في `vercel.json` للنشر اللاحق.
- يحافظ على المدير الموجود. إذا لم يوجد مدير، يحتاج سرين إضافيين `ADMIN_EMAIL` و`ADMIN_PASSWORD` (12–128 حرفًا) لإنشاء حساب يجبر على تغيير الكلمة عند أول دخول. لا توجد كلمة افتراضية؛ غياب السرّين يظهر كتجهيز متبقٍّ، وليس نجاح دخول. إذا فشل ملف المدير يزيل حساب Auth الجديد الذي أنشأه هذا التشغيل فقط.
- يسجل webhook للموقع بعد نجاح فحص الإنتاج، ويفعل pg_cron وpg_net وجدولة الدفعات كل دقيقة باستخدام Vault. مهمة Cron مختلفة موجودة بنفس الاسم تحتاج مراجعة ولا تُستبدل.

التقرير يفرّق بين `deploymentReady` و`websiteReady` و`productionReady`. لا يصبح المشروع كله جاهزًا بمجرد تشغيل API: إنشاء الجروب الخاص وربط المالك وفحصه خطوات متبقية عند المالك، ولا تنشئها Bot API. لا يحاول العامل استرجاع رسائل Telegram أو دعوة/حظر الأعضاء. المستويات وTP/SL ما زالت تسجّل إداريًا، ولا يوجد تتبع سعر سوق آلي.

عند فشل مرحلة بعد تغييرات ناجحة، التقرير يحدد المرحلة والكود الثابت دون إفشاء استجابة المزود. لا يدّعي التراجع الشامل أو يحذف بيانات لاستعادة الحالة؛ راجع التغييرات الجزئية قبل إعادة المحاولة. اختبارات الوحدة تحاكي حدود المزود، واختبار PostgreSQL ينفذ حزمة التهيئة الحقيقية كمعاملة واحدة؛ لا يثبتان وحدهما دعم extensions أو صلاحيات الحساب الحي.

## نتيجة التفعيل الحي — 21 أكتوبر 2026

أثبت [التشغيل 39572925077](https://github.com/mweta66/oldgold/actions/runs/39572925077) أن مخطط Supabase جاهز وأن نشر [wetagold.vercel.app](https://wetagold.vercel.app) اجتاز فحص الصحة، وإرجاع جلسة مجهولة، ورفض قراءة الإشارات دون دخول. اكتمل أيضًا تسجيل webhook للبوت وجدولة إعادة الإرسال كل دقيقة. لم تُنشأ صفقات اختبار أو تُرسل رسائل تجريبية.

لم يُنشأ حساب المدير بعد: يحتاج المالك إضافة `ADMIN_EMAIL` و`ADMIN_PASSWORD` (12–128 حرفًا) في [Repository secrets](https://github.com/mweta66/oldgold/settings/secrets/actions)، ثم إعادة تشغيل **Activate Xgold** من `main`. لا تُرسل القيم في المحادثة. إنشاء الجروب الخاص وإضافة `@Wetagold_bot` وربط حساب المالك ما زالت خطوات متبقية؛ نجاح webhook لا يعني أن الجروب مربوط أو أن الإرسال إليه اختُبر.
