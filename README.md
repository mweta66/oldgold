# WetaGold

منصة عربية لنشر ومتابعة إشارات الذهب، بلوجو ذهبي شفاف وعلامة مائية خافتة وخط Cairo محلي. الإشارات والشارت بعد تسجيل الدخول فقط. المدير الوحيد ينشئ حسابات المشتركين ويحدد الحصة ونهاية التفعيل ويختار ثيم الموقع: ذهبي، أزرق، زمردي أو فاتح.

النشر الجديد يربط **Vercel مباشرةً بـ Supabase Auth وPostgreSQL**؛ لا يحتاج خادم Backend منفصلًا أو SQLite على Vercel. المستودع لا يتضمن مشروع Supabase فعليًا أو مفاتيح أو حسابات إنتاج جاهزة. نجاح البناء لا يعني تفعيل تسجيل الدخول.

## التفعيل والتشغيل

التفاصيل: [دليل Supabase](docs/SUPABASE.md).

1. أنشئ مشروع Supabase وشغّل [migration](supabase/migrations/001_wetagold.sql) مرة واحدة في SQL Editor.
2. أضف `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` في بيئة **الخادم** في Vercel، و`PUBLIC_ORIGIN` لدومين الموقع النهائي و`COOKIE_SECURE=true`. لا تنشر مفاتيح في المتصفح أو Git أو المحادثة.
3. أنشئ أول مدير من بيئة موثوقة بأداة التهيئة أدناه، ثم أعد نشر الموقع. الحساب المحلي السابق لا ينتقل تلقائيًا إلى Supabase. لا تحتاج `BACKEND_ORIGIN`.
4. اختبر `/api/health` ثم تسجيل الدخول وتغيير كلمة المرور المؤقتة وإنشاء مشترك وتغيير الثيم. عند غياب الخدمة، تعرض الواجهة السبب وتعطل الدخول بدل تقديم نجاح وهمي.

استخدم Node.js **24.10 أو أحدث**. أنشئ `.env` محليًا اعتمادًا على `.env.example` واضبط مفاتيح مشروعك و`ADMIN_EMAIL` و`ADMIN_PASSWORD` بشكل سري:

```bash
npm ci
npm run supabase:bootstrap
npm start
```

الأداة ترفض استبدال المدير الموجود وتفرض تغيير كلمة المرور عند أول دخول. استخدم كلمة قوية من 12–128 حرفًا؛ كلمة التهيئة الأقصر لا تعمل إلا إذا سمحت بها سياسة Supabase. احذف كلمة التهيئة من البيئة بعد الإنشاء، ولا تضفها إلى Vercel. لا يوجد حساب افتراضي أو مسار API لإنشاء مدير ثانٍ.

الخادم المحلي على المنفذ 8000. `STORAGE_PROVIDER=supabase` يمنع الرجوع الصامت إلى حسابات SQLite عند نقص الإعدادات. صفحة `/admin` لا تمنح صلاحية؛ الدور يفحص في الخادم وقاعدة البيانات.

## حماية البيانات وحصص الإشارات

- Supabase Auth يتحقق من كلمات المرور؛ المتصفح يأخذ جلسة عشوائية HttpOnly وSameSite=Strict، لا JWT أو مفتاح خدمة. معرّف الجلسة مخزن كـ hash وينتهي بعد 12 ساعة. التعديل يحتاج Origin صحيحًا وCSRF.
- RLS مفعّل وجداول الموقع ودواله محظورة على `anon` و`authenticated`؛ الوصول من API الخادم فقط. الدور لا يؤخذ من metadata يستطيع المستخدم تعديلها.
- الحصة **إجمالي الإشارات الجديدة المخصصة للحساب**، لا عدد مرات فتح الصفحة أو حصة يومية. التخصيص والخصم وطابور Telegram في معاملة PostgreSQL واحدة. تكرار `requestId` لا يخصم مرتين.
- نفاد الحصة يمنع الإشارات التالية، وتبقى متابعة المستلم حتى انتهاء التفعيل. الحساب المنتهي/الموقوف لا يجلب إشاراته. التجديد لا يوزع إشارات قديمة ولا يصفر الاستخدام: رفع الإجمالي من 10 إلى 20 بعد استلام 8 يعني 12 متبقية.
- تعرض الواجهة آخر 200 إشارة ضمن 90 يومًا. نسبة النجاح من النتائج التي سجلها المدير في السجل، وليست نتائج استراتيجية مختبرة.

## الشارت وحدود الإشارات

شارت TradingView الفعلي مثبت على `OANDA:XAUUSD` بفريمي دقيقة و15 دقيقة وتوقيت UTC. لا يوجد سعر ثابت أو صفقات افتراضية. هذا مصدر مختلف عن Bybit وقد يختلف سعر التنفيذ عند وسيط آخر.

**الشارت ليس API لمحرك تداول.** المدير يدخل المستويات بعد مراجعتها. يتحقق الخادم من ترتيب الوقف والهدف وحداثة السعر المرجعي (خمس دقائق) وقرب الدخول منه (2%)، لكنه لا يثبت مطابقته للسوق دون مزود بيانات مرخص. لا توجد استراتيجية AI مدربة أو توليد آلي أو تنفيذ صفقات في هذه النسخة. الإشارات وحدها لا تستطيع فرض حد خسارة على منصة تنفيذ خارجية.

صلاحية الدخول 15 دقيقة؛ المعلقة القديمة تنتهي تلقائيًا. المفتوحة تظل كذلك حتى يسجل المدير الهدف أو الوقف أو الإلغاء. الحد الأقصى إشارتان نشطتان. الإيقاف يمنع نشر الجديد، والمستويات المنشورة لا تعدل وتغييرات الحالات مسجلة.

## Telegram

ضع `TELEGRAM_BOT_TOKEN` و`TELEGRAM_WEBHOOK_SECRET` و`CRON_SECRET` في بيئة الخادم فقط. بعد النشر شغّل `npm run telegram:webhook` من بيئة موثوقة واضبط الجدولة كما في [الدليل](docs/SUPABASE.md#telegram-والإرسال-الدوري).

يربط المشترك البوت من حسابه برابط خاص أحادي الاستخدام صالح لعشر دقائق ثم يضغط Start. النشر يحفظ الرسائل المستحقة في outbox دائم ويبدأ أول دفعة فورًا. العامل يعيد فحص الإشارة والمستلم ويحاول حتى خمس مرات، مع زر إعادة محاولة للمدير. لا يوجد polling دائم داخل Vercel؛ **الجدولة لازمة لبقية الدفعات وإعادة المحاولات**.

`TELEGRAM_ADMIN_CHAT_ID` اختياري لجروب **الإدارة**. الجروب المشترك لا يحترم اختلاف حصص المشتركين؛ التنبيهات المقيدة ترسل في الخاص. لا ندّعي exactly-once: قد تتكرر رسالة إذا قبلها Telegram ثم انقطع الرد. تجهيز الكود لا ينشئ بوتًا أو جروبًا ولا يثبت إرسالًا حيًا.

## الاختبارات والنشر

```bash
npm run check
npm run build:static
npm test
npm run test:browser
npm run format:check
```

اختبارات PostgreSQL تشغل migration والصلاحيات والحصص والدوال فعليًا باستخدام PGlite. اختبارات API تستخدم SDK الحقيقي مع محاكاة شبكة المزود. Chromium يختبر الدخول والصلاحيات والثيمات وتباين الألوان وCairo واللوجو والموبايل وتعطل الخدمة وmanifest بكوكي معاينة. Telegram وTradingView معزولان؛ لا تثبت الاختبارات جاهزية الحسابات الخارجية أو سعر السوق. الصور في `test-results/` مستبعدة من Git. يستخدم المتصفح Chromium المحلي أو `CHROMIUM_PATH` أو تثبيت Playwright.

Vercel يبني ملفات عامة محددة في `dist/` ويشغل API بدالة الخادم. Manifest يرسل credentials لنفس المصدر وCSP يبقى `manifest-src 'self'`؛ لا نسمح بصفحة SSO كأنها manifest. المعاينات تحتاج مشروع اختبار مستقلًا؛ Telegram والجدولة يحتاجان دومين إنتاج عامًا.

النسخ والاستعادة في Supabase تعتمد خطتك وإعدادات مشروعك. لا تعد هذه النسخة بنسخ يومية مجانية أو استعادة اختبرت خارجيًا. SQLite القديم باقٍ للتطوير والاختبارات إذا غابت إعدادات Supabase و`STORAGE_PROVIDER`؛ ليس بديل الإنتاج على Vercel.
