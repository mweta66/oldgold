# WetaGold

منصة عربية لإدارة ونشر إشارات الذهب. الصفحة العامة تعريفية؛ الإشارات تأتي من API محمي بتسجيل الدخول. المدير ينشئ حسابات المشتركين ويحدد حصة كل حساب ونهاية تفعيله، وينشر الإشارات ويتابع حالتها. لا يوجد حساب افتراضي أو أسعار أو صفقات مصطنعة.

## التشغيل

استخدم Node.js **24.10 أو أحدث**. تشغيل Python static server أو GitHub Pages وحده لا يكفي: المصادقة وقاعدة البيانات وTelegram تحتاج خادم Node.

```bash
npm ci
npm start
```

الخادم المحلي على المنفذ `8000` افتراضيًا. صفحة `/admin` تطلب تسجيل الدخول؛ صلاحية المدير تتحقق في الخادم، وليس في عنوان الصفحة أو عناصر الواجهة.

قبل أول تشغيل، أنشئ ملف `.env` محليًا اعتمادًا على `.env.example`. املأ `ADMIN_EMAIL` و`ADMIN_PASSWORD` بكلمة قوية من 12–128 حرفًا. هذه الخطوة تنشئ **أول مدير فقط** إذا لم يوجد مدير في قاعدة البيانات. لا تضع القيم في Git أو المحادثة. بعد الإنشاء، احذف كلمة التهيئة من إعدادات التشغيل واستخدم تغيير كلمة المرور داخل الحساب. لا يؤدي تغيير متغير التهيئة لاحقًا إلى استبدال الحساب الموجود.

يدعم تهيئة أول مدير بكلمة مؤقتة من 6–128 حرفًا. إذا كانت أقصر من 12، أو كان `ADMIN_REQUIRE_PASSWORD_CHANGE=true`، لا تسمح الجلسة إلا بتغيير كلمة المرور والخروج. صفحة الإدارة والإشارات لا تفتح حتى يستبدلها المدير بكلمة من 12–128 حرفًا ويسجل الدخول مجددًا. الحسابات التي ينشئها المدير تظل تتطلب 12 حرفًا من البداية. لا يوجد مسار في API لإنشاء مدير ثانٍ أو ترقية مشترك إلى مدير.

قاعدة SQLite الدائمة تحفظ في `data/wetagold.sqlite`؛ المجلد وملفات `.env` مستبعدة من Git. تخزن كلمات المرور باستخدام scrypt مع salt، والجلسات على الخادم باستخدام hash للمعرّف. الجلسة تنتهي بعد 12 ساعة، وتلغى الجلسات عند تغيير كلمة المرور أو إيقاف الحساب.

## تعريف حصة الإشارات

- الحصة هي **إجمالي الإشارات الجديدة المخصصة للحساب خلال تفعيله**، وليست عدد مرات فتح الصفحة أو عددًا يوميًا.
- عند النشر، تُخصص الإشارة مرة واحدة لكل حساب مفعّل لم ينتهِ ولديه حصة متبقية. تخصم الحصة في نفس معاملة قاعدة البيانات.
- النشر المتكرر بنفس معرّف الطلب لا ينشئ إشارة ثانية ولا يخصم مرتين. تحديث الصفحة لا يخصم.
- نفاد الحصة يمنع الإشارات التالية؛ تبقى متابعة الإشارات المستلمة متاحة حتى انتهاء التفعيل.
- الحساب المنتهي لا يستطيع جلب إشاراته. التجديد أو زيادة الحصة يسري على الإشارات التالية، دون توزيع إشارات قديمة تلقائيًا.
- تعديل الحصة يغير الإجمالي، ولا يصفر الاستخدام. مثلًا: مستلم 8 من أصل 10، وتجديده إلى إجمالي 20 يعني 12 متبقية.
- تعرض الواجهة آخر 200 إشارة ضمن 90 يومًا. النسبة المعروضة محسوبة فقط من الحالات المغلقة في هذا السجل، المسجلة بواسطة المدير؛ ليست نتائج استراتيجية مختبرة.

## الشارت والإشارات

الشارت المضمّن من TradingView مثبت على `OANDA:XAUUSD`. يتطابق الزر المختار مع الفريم (دقيقة/15 دقيقة)، مع تكبير اختياري وتوقيت UTC. لا يُكتب سعر ثابت على الصفحة ولا تُسحب أسعار من محتويات iframe عبر وسائل غير مدعومة.

**مصدر الشارت ليس API لمحرك الإشارات.** المستويات الحالية يدخلها المدير من مصدر OANDA بعد مراجعتها. يتحقق الخادم من ترتيب الوقف/الهدف، وحداثة السعر المرجعي (خمس دقائق)، وقرب الدخول منه (2%). لا يمكن للخادم إثبات أن السعر المدخل يطابق السوق دون إضافة مزود أسعار مرخص. لا توجد استراتيجية AI مدربة أو توليد تلقائي للصفقات في هذه النسخة.

تبقى الإشارة معلقة لمدة 15 دقيقة، وتتحول تلقائيًا إلى منتهية إذا لم يفتحها المدير. الإشارة المفتوحة تظل مفتوحة حتى يسجل المدير الهدف أو الوقف أو الإلغاء. لا يعد انتهاء صلاحية الدخول إغلاقًا تلقائيًا للصفقة. الحد الأقصى إشارتان نشطتان؛ زر الإيقاف يمنع نشر إشارات جديدة. المستويات غير قابلة للتعديل بعد النشر، والتغييرات مسجلة في سجل الإدارة.

## Telegram

1. أنشئ بوتًا عبر `@BotFather`. احفظ `TELEGRAM_BOT_TOKEN` في إعدادات الخادم السرية. أعد تشغيل الخادم بعد تغيير الإعدادات.
2. من لوحة المدير، استخدم «فحص اتصال البوت». لا يعرض الموقع التوكن ولا يستقبله من المتصفح.
3. كل مشترك يضغط «ربط Telegram» من حسابه، ثم يفتح الرابط ويضغط Start. رابط الربط صالح لعشر دقائق ويستخدم مرة واحدة في محادثة خاصة. البوت يقرأ تحديثاته كل خمس ثوانٍ. يجب إلغاء أي webhook قديم للبوت قبل استخدام long polling، وتشغيل نسخة واحدة من التطبيق.
4. عند نشر إشارة، تضاف رسائل أصحاب الصلاحية إلى قائمة إرسال دائمة ثم يبدأ الإرسال تلقائيًا. نفاد الحصة يمنع تخصيص الإشارات التالية على الموقع وTelegram معًا. فك الربط أو إيقاف الحساب يلغي رسائله المعلقة.
5. اختياريًا: أنشئ جروب **للإدارة** وأضف البوت بصلاحية إرسال، واحفظ رقمه في `TELEGRAM_ADMIN_CHAT_ID`. تصله جميع الإشارات. لا تستخدمه لجمع المشتركين ذوي الحصص المختلفة، لأن العضوية في جروب مشترك تكشف رسائله للجميع.

يفحص عامل الإرسال صلاحية المستلم والإشارة مجددًا قبل كل محاولة. يعيد المحاولة تدريجيًا حتى خمس مرات، ثم يعرض الفشل للمدير مع زر إعادة المحاولة. يحتفظ بمعرّف الإشارة في الرسالة. مثل أي إرسال عبر Telegram، قد تصل رسالة مكررة إذا نجح الطلب عند Telegram ثم انقطع الرد؛ لا ندّعي ضمان exactly-once. الإشارات القديمة لا تعاد تلقائيًا بعد ربط البوت.

## النسخ الاحتياطي والنشر

تؤخذ نسخة SQLite متسقة مرة يوميًا عند عمل الخادم، مع فحص كل ساعة، إلى `BACKUP_DIR` (افتراضيًا `data/backups`). لا يستبدل التطبيق نسخة موجودة لنفس اليوم. صلاحيات المجلد `0700` والملف `0600`. الحالة تظهر للمدير. لا تحذف النسخ تلقائيًا؛ راقب مساحة القرص. انقل نسخة مشفرة خارج الخادم للحماية من تلف القرص بالكامل.

لاستعادة نسخة: أوقف التطبيق، احتفظ بكل ملفات قاعدة البيانات الحالية بما فيها `-wal` و`-shm` خارج مسار الاستعادة، ضع النسخة في مسار **جديد** واضبط `DATABASE_PATH` عليه، ثم شغل التطبيق وتحقق من الحسابات والسجل قبل إعادة استقبال المستخدمين.

للنشر اضبط `NODE_ENV=production` و`PUBLIC_ORIGIN=https://your-domain` و`COOKIE_SECURE=true`، وضعه خلف HTTPS reverse proxy مع تخزين دائم لقاعدة البيانات والنسخ الاحتياطية. يفشل بدء الإنتاج إذا غاب HTTPS أو الكوكي الآمن. لا توجد تبعيات npm وقت التشغيل؛ `npm ci --omit=dev` كافٍ للتشغيل. استخدم نسخة خادم واحدة مع SQLite والبوت. عند الحاجة لعدة نسخ، انقل التخزين وطابور الرسائل إلى خدمة مشتركة أولًا.

### عند استخدام Vercel الحالي

يتضمن المستودع `vercel.json` وبناء `npm run build:static` ينشر ملفات الواجهة فقط من `dist/`، ودالة `/api/[...path]` تمرر الطلبات إلى خادم Node الدائم. لا تشغل SQLite أو عامل Telegram داخل Vercel Functions، لأن التخزين المحلي هناك غير دائم.

1. شغّل خادم Node من المستودع على استضافة ذات قرص دائم. أنشئ المدير بإعداد `ADMIN_EMAIL` و`ADMIN_PASSWORD` هناك، وأضف إعدادات البوت هناك أيضًا.
2. اضبط `PUBLIC_ORIGIN` على دومين الواجهة النهائي في Vercel، و`COOKIE_SECURE=true` و`NODE_ENV=production` في الخادم. الخادم يحتاج HTTPS أيضًا.
3. في إعدادات مشروع Vercel أضف `BACKEND_ORIGIN=https://your-persistent-backend-domain` بدون مسار، ثم أعد نشر الواجهة. لا تضع مفاتيح البوت أو كلمة مرور المدير في ملفات الواجهة.
4. عند غياب ربط الخادم تعيد الدالة 503 ورسالة واضحة؛ نجاح بناء واجهة Vercel وحده لا يثبت جاهزية تسجيل الدخول. اختبر إنشاء حساب وتسجيله بعد ضبط الإعدادات.

دومين المعاينة يختلف عن دومين الإنتاج. استخدم خادم اختبار منفصلًا مع `PUBLIC_ORIGIN` المطابق للمعاينة، ولا توجه المعاينات غير الموثوقة إلى قاعدة بيانات الإنتاج.

الدومينات الخارجية: `www.tradingview.com` للشارت في متصفح المستخدم، و`api.telegram.org` للبوت من الخادم، ودومين الخادم الدائم عند استخدام Vercel. تحتاج عمليات Pull Request إلى `api.github.com` بالإضافة إلى وصول Git للمستودع.

## التحقق

```bash
npm run check
npm test
npm run test:browser
```

يستخدم اختبار المتصفح Chromium المثبت في `/usr/bin/chromium`، أو `CHROMIUM_PATH`، أو نسخة Playwright (`npx playwright install chromium`). يشمل مستخدمًا ومديرًا وشاشتي كمبيوتر وموبايل. اختبارات Telegram والشارت الخارجية تستخدم حدودًا محاكية دون إرسال رسائل حقيقية؛ لا تثبت توفر مزودي الخدمة. صور الواجهة الناتجة في `test-results/` ومستبعدة من Git. تنفذ GitHub Actions الاختبارات على Node 24.

راجع [تقرير المراجعة والتحسينات](docs/AUDIT.md) للنتائج والقيود المتبقية.
